Security & Authorization Blueprint

JWT Cookie & Role-Based Authorization

Strict security contract isolating Customer and Admin privilege boundaries.

1. USER LOGIN POST /auth/login
2. BCRYPT CHECK Password Match
3. JWT COOKIE httpOnly Token
4. AUTHEN Sets req.user
ROLE: CUSTOMER
  • • Access Personal Cart & Address Book
  • • Place Orders & View Order History
  • • Access Profile Settings
ROLE: ADMIN (`authorize("admin")`)
  • • Full Product Inventory Mutation (CRUD)
  • • Modify Order Delivery Statuses
  • • Edit Blog & System Content Articles

Engineering Resolutions

Problem $\rightarrow$ Solution $\rightarrow$ System Impact

Core technical bottlenecks solved during final system integration.

PROBLEM 01: Client-side Identity Spoofing

Unprotected User IDs in API Query Parameters

Early cart and address endpoints relied on client-supplied user_id strings, creating vulnerability to identity spoofing.

SOLUTION: Replaced with httpOnly JWT authentication where identity is verified via server-side req.user._id.
PROBLEM 02: Price Manipulation Risk

Client-side Order Total Calculation

Calculated checkout prices inside local React state allowed potential price manipulation before database save.

SOLUTION: Enforced backend cart re-read and server-side atomic price calculation before order creation.
